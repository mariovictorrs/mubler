# ADR-0002: ListenBrainz API compatibility

- **Status:** Proposed
- **Date:** 2026-10-17

## Context

Clients such as Navidrome already support ListenBrainz and allow configuring the base URL. If mubler speaks that protocol, no client needs to be modified.

## Decision

Implement a subset of the ListenBrainz v1 API under the `/1/` prefix:

1. `POST /1/submit-listens` — `listen_type` `single`, `import`, `playing_now`; payload limits equivalent to the official service.
2. `GET /1/validate-token` — validates the token.
3. `GET /1/user/{user}/listens` — history reads (later phase).

Authentication via the `Authorization: Token <token>` header. Success responses are `{"status": "ok"}`; errors are `{"code": <http>, "error": "<message>"}`.

Tokens are generated by mubler (they are not ListenBrainz tokens).

## Alternatives considered

- **Custom API + per-client plugin** — more work and fragmentation.
- **Last.fm/AudioScrobbler compatibility** — possible later as a separate adapter.

## Consequences

- Any LB-compatible client works by pointing its base URL at mubler.
- We must track the official documentation to stay faithful; see the `listenbrainz-compat` skill.
